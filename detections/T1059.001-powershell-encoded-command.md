# T1059.001 - PowerShell Encoded Command

**Tactic:** Execution
**Data source:** Sysmon EventCode 1 (Process Creation)

## Detection (SPL)
```spl
index=sysmon EventCode=1 Image="*\\powershell.exe" (CommandLine="* -enc *" OR CommandLine="* -EncodedCommand *")
| table _time, host, User, ParentImage, CommandLine
```

## Why it works
Attackers encode PowerShell payloads in base64 to hide them from simple string matching. The flag itself is visible in the command line.

## How I tested it
I generated the encoded string in PowerShell from the plain text `whoami`, then ran it with `-EncodedCommand`. Generating the string rather than typing it avoids typos in the base64.

<img width="800" alt="Splunk showing a PowerShell process launched with the EncodedCommand flag" src="https://github.com/user-attachments/assets/fc732c97-15c9-45af-8a18-758267043dbd" />

*Splunk detecting `powershell.exe -EncodedCommand` on the domain controller. The base64 string decodes to `whoami`, a harmless test payload.*

The rule keys on the `-EncodedCommand` flag in the process command line, so it fires even when the decoded payload fails to run.

## Alerting

Scheduled to run every 5 minutes over a 5-minute window, and to trigger on any result. Severity is High, because encoded commands are commonly used to hide payloads.

## False positives
Some management and deployment tools use encoded commands. Tune by parent process and known tooling.
